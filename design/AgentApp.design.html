Most of the menu went nowhere

Nine screens, thirty menu destinations, and six of them existed. This is what changed, and why each change is the one worth making.

24 of thirty sidebar links answered with Next's default 404. Not features the customer hadn't bought — features their plan granted, promised in the navigation, leading nowhere. A paid feature that 404s doesn't read as unfinished. It reads as broken.

A dead link becomes an answer

There were already good answers for two of the three ways a screen can be unreachable: not on your plan gets an upgrade prompt, switched off for everyone gets a maintenance notice. The third — we haven't built it yet — had none.

It never gives a date, because we don't have one and a missed date is worse than none. And it always offers somewhere to go: a dead end that apologises is still a dead end.

Smaller things, same pass

  • No more ticket numbers “No policies yet — this screen is scaffolding for LA-0.1” was shown to paying customers. Empty states now say what will fill the screen and where it comes from.
  • plan_c → Plan C And the version number is gone. It tells an operator which plan version an entitlement came from; it tells a customer that something they don't understand has changed three times.
  • The min-w-0 fix The same bug the admin shell had: a flex item won't shrink below its widest child, so one wide table drags the whole page sideways. Fixed here before there's a table to prove it.
  • A test that stops the regression The built flag and the filesystem must agree. Adding a screen and forgetting to flip it now fails in CI rather than in front of a customer — which is exactly how 24 dead links happened.
