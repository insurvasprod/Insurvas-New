Settings › Application forms

The lead intake form a partner or agent fills in to create a lead, one per product (Final Expense, Term life, Medicare…), copied from the Insurvas form for that product. Today it is a careful single-form editor: one draft kept in this browser until Publish version N, questions moved with up/down arrows, one “show after X = Y” condition each, and no way to test, share, hook up or measure the form. The owner wants it as easy to set up as Typeform, Jotform, HubSpot forms or Tally, using every feature we already have and adding the ones premium form builders take for granted.

1 · One form per product, and no way to make anotherNo create, no duplicate. An agency that runs a Spanish Final Expense form, or a short web form next to a long partner form, cannot. Several forms per product is the biggest gap. needs a migration
2 · The draft lives in one browserClose the laptop, switch machines or let a teammate help, and the work is gone. Publish controls also show twice (header and bottom bar). Drafts should be saved to Insurvas and publish should live in one place. needs a migration
3 · Logic is one condition, order is arrows“Show after X = Y” cannot say “Tobacco is Yes and age is over 60”. Arrows make a 13-question form slow to arrange. There are no pages or steps, so phone users scroll one long list.
4 · Nothing to prove the form works“Try the form” fills a dialog but creates nothing. There is no test submission that shows the lead, its pipeline stage and where each answer landed on the application.
5 · The form cannot leave InsurvasNo share link, embed code or QR for an agency website or a mailer, no webhook when a form is sent, no numbers on starts, completions or where people stop.
Forms vs Application field setsThe application form (this page) creates the lead: what a partner, agent or website visitor answers up front. Application field sets are the carrier’s paper application per carrier × product, deciding which fields are Not asked / Optional / Required on the case’s Application step later. Answers flow from form to application by matching field names; every option below shows that match openly so it is not a guess.

Pick one

Nothing is built until you choose
A · Three-pane builder (recommended)The pattern people already know from Jotform and HubSpot: drag a field in, see the form, set it on the right. Keeps today’s canvas and side panel, so it is the shortest path from what is built.
  • Several forms per product, create from Insurvas, a copy or blank needs a migration
  • Draft saved to Insurvas, one Publish, versions with “what changed” needs a migration
  • Drag to reorder and drag in Insurvas questions; pages needs a migration
  • AND / OR logic, page skips, validation with “try a value”
  • Test submission that shows the lead and where each answer landed
  • Share link, embed, QR, webhook, results needs a migration
B · One question at a timeTypeform-style: the form is a deck of question cards and logic reads as a flow. Best for website leads on phones; slower for agents who fill a long form during a call.
  • Everything new in A, but one question per screen for the person filling it in
  • Logic as a flow map (“If Tobacco = Yes → Smoking questions”)
  • Results per question as a bar run
  • Biggest change from today’s form; partner portal would need a second renderer
C · Overview + sectionsA forms library first, then a calm section-by-section editor with inline editing, no side panel. Easiest for a first-time owner; less room for heavy logic.
  • Everything new in A, edited in place instead of in an inspector
  • Library page with every product’s forms and their numbers
  • Logic and rules open under the question they belong to
  • Closest to how Settings pages already look
