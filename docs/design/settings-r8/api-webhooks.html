Settings › API keys & webhooks

This page lets the agency connect other software to Insurvas: an API key lets another app (Zapier, a reporting warehouse, an old CRM) read or send data; a webhook tells another app the moment something happens (a policy is issued or lapses, a commission doesn't match). Today the page works and follows the security spec (key hash only, shown once, scopes, 24 h rotation overlap, signed deliveries), but it reads like a developer console: two paged tables of prefixes and monospace URLs, dialogs for everything, no way to see who is connected at a glance, and lead-vendor keys live on a different page under the same word "key".

1 · Two kinds of "key", no mapAPI keys live here; lead-posting keys live in Lead posting. Nothing tells the owner which apps, vendors and endpoints are connected right now, or where each one is managed.
2 · Developer words on the surfaceKey prefix + last four, raw scope names, the target URL in monospace, the last IP address in the table. The owner who has to approve a key can't tell what it can actually do.
3 · A failing webhook is a number on a tab"Webhooks 1 failing" shows on the tab, but the why (their server answered 500 five times) is three clicks away inside a log dialog, and there is no Retry.
4 · Everything is a dialogCreate, rotate, add webhook, delivery log, show-once secret: five dialogs, each forgetting where you were. Records should open as a right sheet with the list still behind it.
5 · Nothing to hand a developerAfter the key is shown once there is no code sample, base address, or "how to check our signature". The owner forwards a key with no instructions.
6 · The 90-day idle rule is silentThe spec asks to prompt about keys nobody uses; today an idle key only shows a grey date. Unused keys are the ones nobody notices being abused.

Check the signature

Every delivery carries a timestamp and a signature made with your webhook's signing secret. Refuse anything older than 5 minutes or with a signature that doesn't match.

Header
Insurvas-Signature: t=1731424860,v1=5f3c…
Signed text
the timestamp, a dot, then the raw body
Method
HMAC with SHA-256, using the signing secret
curlJavaScriptCopy
import crypto from "node:crypto"; export function isFromInsurvas(rawBody, header, secret) { const { t, v1 } = Object.fromEntries(header.split(",").map((p) => p.split("="))); if (Math.abs(Date.now() / 1000 - Number(t)) > 300) return false; // older than 5 min const expected = crypto.createHmac("sha256", secret).update(`${t}.${rawBody}`).digest("hex"); return crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(v1)); }

What a delivery looks like

Policy issued. Names and figures only; never a Social Security number, bank details or health answers.
