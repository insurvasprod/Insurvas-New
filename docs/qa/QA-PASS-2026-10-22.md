# QA pass, 22 Oct 2026: independent agent, modules 1–8

A hands-on walk through the app, from the landing page through sign-up, plan, team, leads, dialer,
pipelines, applications, book and isolation. Done in the built-in browser against the local dev server
(which talks to the production Supabase project). **Nothing is committed.** Screenshots are in
[`docs/qa-screenshots/qa-pass-2026-10-22/`](../qa-screenshots/qa-pass-2026-10-22/). For colleagues,
start with [REVIEWER-GUIDE.md](REVIEWER-GUIDE.md).

Each result is marked **PASS**, **FIXED** (a bug I fixed and re-tested in the browser), **OPEN** (left
for the owner) or **NOTE**.

## Summary

- **Isolation holds.** Agent A and A's producer could not reach any of agent B's leads, policy,
  contact, campaign, application, callback or import, by search, lists, exports, API IDs or page URLs
  (§6).
- **13 bugs fixed.** The ones that blocked a new customer: a staff-comped sign-up was stuck at
  checkout, Resend invite always failed, Add contact always failed, a race broke List import on its
  first visit, typing an expiry date crashed Settings, and a typed spend of "abc" was saved as $0.00.
- **Two high-severity gaps need you.** (1) The Agency plans have no products in the catalog, so List
  import and the whole Lead workspace fail for every Agency customer. (2) A new workspace has no call
  outcomes mapped to pipeline stages, so dialing never moves a lead until all 14 are mapped by hand.
- **Not reached:** inbound screening, verification and handoff (it needs a partner sending a live
  transfer), submitting an application to a carrier, carrier file and statement imports, retention
  campaigns, and creating records in accounting and compliance. Those were checked only to the point
  of each page loading without errors (all 57 menu pages, §5.9). **Part 2 (§8) walked them all**,
  except agent-to-agent hand-off and anything fed by carrier files, which waits on staff approving
  carrier status words.

### 8.1 Summary

- **Inbound works end to end for a single agent.** I created a partner, activated it, and gave it a
  product, terms and carrier/state access. Its portal user submitted a transfer. B claimed it, verified
  all six fields, recorded an outcome and went on into an application.
- **An application went all the way to Book.** The steps were interview, quote, application,
  beneficiaries, payment, review (19 checks), captured submission and issued. **QA-MOO-POL-0001** then
  appeared under Book › Policies › *Recorded sales*. That needed one fix: before it, an issued sale
  recorded without a policy number could never reach Book (§8.3).
- **I fixed two high-severity bugs in the partner portal.**
  - Money a partner typed was stored 100× too small: a coverage of 250000 reached the agent as $2,500.
  - A slow refresh wiped the screened phone number, so the draft saved "0 answers".
- **Blocked until Insurvas staff act:** carrier-file rows stay *held* until staff approve the carrier's
  status words.
  - Mutual of Omaha has no approved status words, so "Active" is unmapped.
  - This blocks policy matching, the commission ledger, discrepancies, the save queue, reinstatement
    and win-back. None of them could be fed from a QA file.
  - The status map is shared by every customer, so I left it alone on production.
- **Not reached:** a hand-off between agents (§8.2), and a commission statement import, which hits the
  same status-word blocker.
