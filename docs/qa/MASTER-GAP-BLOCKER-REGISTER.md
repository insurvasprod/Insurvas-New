## Operating rules

- Work in task order and close the smallest safe batch before starting the next batch.
- Preserve the existing shared Supabase project, shared records, and dirty worktree.
- Use only namespaced disposable fixtures for live tests.
- Do not apply a migration without DDL authority, a reviewed impact, and an additive/reversible plan.
- Keep real payment, email, telephony, carrier, tax, compliance, and production integrations disabled.
- A browser-unverified item is not a frontend pass; a database-misaligned item is not an implementation pass.
